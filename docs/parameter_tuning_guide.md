# 参数调优实战指南

本指南旨在帮助你根据 `config.yaml` 中的参数，系统地优化 Bathymetric SLAM 的性能。我们将遵循从宏观到微观的顺序，确保每一步调整都有明确的目标和可观测的反馈。

## 总体调参流程（推荐顺序）

1. **保障数据质量**：首先调整点云下采样参数，在特征保留与计算效率之间找到平衡。
2. **设定子图尺寸**：确定 `submap_size`，以保证单个子图的几何结构稳定。
3. **优化重叠检测**：调整 `overlap_coverage`，以产生数量适中且质量较高的候选配准对。
4. **确保 GICP 稳定收敛**：配置 GICP 的核心参数，如距离阈值和迭代次数，确保点云配准的鲁棒性。
5. **校准图优化权重**：精调信息矩阵 (`gicp_info_diag`) 和里程计噪声 (`dr_noise_*`)，以平衡不同约束在图优化中的影响。
6. **确认闭环协方差策略**：选择 `lc_edge_covs_type`，决定闭环边的不确定性来源。
7. **微调 GICP 停止条件**：在需要时，进一步调整 GICP 的收敛阈值以优化精度和耗时。

---

## 1. 点云下采样（Voxel Grid Downsampling）

**相关参数**:
- `downsampling_leaf_x`
- `downsampling_leaf_y`
- `downsampling_leaf_z`

**目的**: 平衡点云的细节保留、噪声抑制和计算负载。这是预处理的第一步，对后续所有环节都有深远影响。

**调节策略**:

- **体素尺寸过小**: 保留了更多细节，但增加了 GICP 的计算时间，且对噪声更敏感。
- **体素尺寸过大**: 减少了计算量并能抑制部分噪声，但可能丢失关键的几何特征，导致配准精度下降或失败。

**建议步骤**:

1. 从一个相对保守的值开始，例如 `0.2, 0.2, 0.1`。
2. 观察指标：GICP 的配准耗时、成功率以及最终地图的质量。
3. 如果配准失败率高或局部细节丢失严重，尝试将体素尺寸**减小** 20-30%。
4. 如果配准稳定但耗时过长，可以尝试**增大**体素尺寸 10-20%，以提升效率。

---

## 2. 子图尺寸（Submap Size）

**相关参数**:
- `submap_size`

**目的**: 定义每个子图包含的 ping 数量。它直接影响子图的几何稳定性和重叠检测的频率。  
**注意**: 当使用自己的子地图数据集时，则忽略 `submap_size` 参数

**调节策略**:

- **过小**: 子图的几何结构可能不够稳定，导致 GICP 配准失败。但优点是能更频繁地检测重叠。
- **过大**: 子图更稳定，但寻找闭环的机会减少，同时内存和计算开销增大。

**经验法则**:

- 对于新数据集，可以从 `100` 左右开始尝试。
- 如果数据稀疏或噪声较大，应**增大**此值（例如 `150-200`），以形成更可靠的几何结构。
- 如果 GICP 配准失败率高，且日志显示子图几何形状不稳定，应**增大**此值。
- 如果轨迹漂移明显且闭环边数量过少，可以尝试**减小**此值，以创造更多重叠机会。

---

## 3. 子图重叠检测（Submap Overlap Detection）

**相关参数**:
- `overlap_coverage`

**目的**: 判定两个子图是否重叠到足以进行配准的程度。这是一个关键的“门槛”参数。

**调节策略**:

- **降低此值** (e.g., from `0.7` to `0.5`): 会产生更多的候选配准对。这能增加找到有效闭环的机会，但也引入了更高的计算量和潜在的错误匹配风险。
- **提高此值**: 使重叠条件更严格，从而减少候选对数量。这有助于避免错误匹配，但可能导致错过有效的闭环，使轨迹漂移无法被修正。

**建议步骤**:

1. 从一个中间值开始，如 `0.6`。
2. 如果闭环数量不足（通过日志或 `loop_closures.txt` 文件判断），逐步**降低**此值（例如，以 0.1 为步长）。
3. 如果出现明显的错误闭环（优化后的地图出现扭曲或撕裂），应**提高**此值。
4. **注意**: 在调整此参数前，请确保 `submap_size` 没有设置得过大，因为过大的子图本身就会减少重叠机会。

## 4. GICP 配准参数（Point Cloud Registration）

这是确保点云配准质量的核心。

### **核心参数**:

- `gicp_max_correspondence_distance`: 剔除远距离匹配点的阈值。
  - **过大**: 容易引入错误匹配，导致配准失败或结果错误。
  - **过小**: 如果初始位姿估计不准，可能导致找不到足够的有效匹配，从而使配准失败。
  - **建议**: 根据你的作业场景，设置为一个略大于预估最大误差的“保守”值。例如，如果水深变化在 5 米内，可以从 10-15 米开始尝试。
- `gicp_maximum_iterations`: GICP 的最大迭代次数。
  - 通常 `200` 次已经足够。如果频繁达到迭代上限仍不收敛，说明其他参数（很可能是 `gicp_max_correspondence_distance`）设置不当。
- `gicp_transform_epsilon` / `gicp_euclidean_fitness_epsilon`: 收敛停止的阈值。
  - 减小这些值可以提高配准精度，但会增加计算耗时。通常无需优先调整。
- **法线估计相关**:
  - `gicp_normal_use_knn_search`: 推荐设为 `true`。
  - `gicp_normal_search_k_neighbours`: K近邻搜索的点数。如果点云密集且平滑，`30` 是一个不错的起点。如果地形复杂或点云密度变化大，可适当增加到 `40-50`。

### 参数详解

这些参数是点云配准（Registration）的核心，直接决定了两个子地图能否精确地对齐。相关的代码逻辑主要在 `registration/gicp_reg.hpp` 和 `bathy_slam/bathy_slam.hpp` 中实现，它们调用了PCL（Point Cloud Library）的GICP功能。

#### 1. `gicp_max_correspondence_distance`

*   **参数含义**：**最大对应点对距离**。在GICP算法的迭代过程中，它会为源点云中的每个点在目标点云中寻找一个“对应点”。这个参数设置了一个距离阈值（单位：米）。如果找到的对应点与源点之间的距离超过了这个阈值，那么这对点就会被认为是错误的匹配（outlier）而被忽略。

*   **代码中的体现**：
    在 `registration/gicp_reg.hpp` 中，这个值被用来设置GICP对象的参数：
    ```cpp
    // pseudo-code from gicp_reg.hpp
    pcl::GeneralizedIterativeClosestPoint<PointT, PointT> gicp;
    gicp.setMaxCorrespondenceDistance(config.gicp_max_correspondence_distance);
    ```

*   **调参方法与影响**：
    *   **调大该值**：允许算法在更广的范围内搜索对应点。
        *   **优点**：当两个子地图的初始位姿估计偏差较大时，较大的搜索范围能帮助算法找到初始的匹配，从而启动配准过程。
        *   **缺点**：非常容易引入错误的匹配。想象一下，如果两个相距很远但形状相似的波浪被错误地匹配在一起，会导致配准结果完全错误，甚至导致优化后的地图出现严重的扭曲。
    *   **调小该值**：将搜索范围限制在一个很小的邻域内。
        *   **优点**：能非常有效地排除错误的匹配，确保只有真正靠近的点才会被用来计算变换，从而提高配准的精度和鲁棒性。
        *   **缺点**：如果初始位姿估计不准，或者两个子地图的真实位移就很大，过小的搜索范围可能会导致算法找不到任何有效的对应点，从而使配准失败。

    *   **调节建议**：这是一个**最关键的GICP参数**。你应该根据你对传感器定位误差的先验知识来设定它。例如，如果你估计两次测量之间的漂移误差在5米以内，那么可以将这个值设置为10-15米，给一个合理的余量。如果配准频繁失败且出现“扭曲”的闭环，应优先**减小**此值。

#### 2. `gicp_maximum_iterations`

*   **参数含义**：**GICP算法的最大迭代次数**。GICP是一个迭代优化过程，它会不断地计算变换矩阵，直到满足收敛条件或达到最大迭代次数。

*   **代码中的体现**：
    ```cpp
    // pseudo-code from gicp_reg.hpp
    gicp.setMaximumIterations(config.gicp_maximum_iterations);
    ```

*   **调参方法与影响**：
    *   这个参数通常不需要精细调节。`200`次对于绝大多数场景来说都足够了。
    *   如果算法频繁地因为达到最大迭代次数而终止，这通常**不是迭代次数不够多**的问题，而是其他参数设置不合理的信号，最常见的原因是 `gicp_max_correspondence_distance` 设置得过大，引入了太多错误匹配，导致算法无法收敛。你应该去检查其他参数，而不是单纯地增加迭代次数。

#### 3. `gicp_transform_epsilon` / `gicp_euclidean_fitness_epsilon`

*   **参数含义**：**收敛判断阈值**。这两个参数定义了GICP算法何时停止迭代。
    *   `gicp_transform_epsilon`：当两次迭代之间计算出的变换矩阵（平移和旋转）差异小于这个阈值时，认为算法已经收敛。
    -   `gicp_euclidean_fitness_epsilon`：当对应点对的均方根误差（RMSE）小于这个阈值时，认为配准质量已经足够好，算法收敛。

*   **代码中的体现**：
    ```cpp
    // pseudo-code from gicp_reg.hpp
    gicp.setTransformationEpsilon(config.gicp_transform_epsilon);
    gicp.setEuclideanFitnessEpsilon(config.gicp_euclidean_fitness_epsilon);
    ```

*   **调参方法与影响**：
    *   **减小该值**：会让收敛条件更严格，算法会进行更多次迭代来追求更高的精度，但这会增加计算耗时。
    *   **增大该值**：会让算法更容易“满足”并提前停止，速度更快，但可能会牺牲一定的配准精度。
    *   **调节建议**：通常情况下，默认值 `1e-3` 是一个很好的平衡，无需优先调整。只有在你对配准精度有极高要求，并且愿意牺牲时间的情况下，才考虑适度减小它们。

#### 4. `gicp_normal_use_knn_search` / `gicp_normal_search_k_neighbours`

*   **参数含义**：**点云法向量的计算方式**。GICP算法不仅考虑点的位置，还考虑点所在平面的方向（即法向量），这使得它对旋转的估计更鲁棒。
    *   `gicp_normal_use_knn_search`: 是否使用K近邻（KNN）方法来估计法向量。如果为 `true`，则使用下面一个参数。如果为 `false`，则会使用半径搜索。
    *   `gicp_normal_search_k_neighbours`: 当使用KNN方法时，用每个点周围最近的 `k` 个邻居来拟合一个平面，从而计算出该点的法向量。

*   **代码中的体现**：这部分通常在点云预处理阶段完成，在 `bathy_slam.hpp` 中，点云在被送入GICP之前会先计算法向量。

*   **调参方法与影响**：
    *   `gicp_normal_use_knn_search`: 对于水下测深这种点云密度相对均匀的场景，使用KNN（设置为 `true`）通常比半径搜索更稳定。
    *   `gicp_normal_search_k_neighbours`:
        *   **值过小**：法向量估计可能对局部噪声非常敏感，导致法向量方向不稳定。
        *   **值过大**：会平滑掉一些细节特征，比如一个尖锐的岩石边缘可能会被“磨平”。
        *   **调节建议**：`30` 是一个非常经典的起点。如果你的海底地形非常平坦，可以适当减小此值。如果点云噪声较大或地形非常复杂，可以适当**增大**此值（例如到 `40` 或 `50`），以获得更平滑、更鲁棒的法向量估计。

## 5. 图优化权重（Graph Optimization Weights）

这部分参数决定了不同约束（GICP配准边 vs. 里程计边）在图优化过程中的相对重要性。

**GICP 信息矩阵**:

- `gicp_info_diag`: 格式为 `[x, y, z, rotation]`。
- **含义**: 定义了 GICP 配准结果的可信度。值越大，表示对该自由度的约束越强，优化时越不容易被改变。
  - 前三个值分别对应 x, y, z 三个平移方向的置信度。
  - 最后一个值对应旋转（Roll, Pitch, Yaw）的置信度。
  - GICP对平移的估计比对旋转的估计要可靠10倍。这在水下环境中通常是合理的，因为从海底地形点云中精确恢复平移相对容易，而旋转则可能存在更多不确定性。
- **调节逻辑**:
  - 如果优化后的地图在水平方向（X, Y）漂移或错位，**增大**前两个值。
  - 如果在深度（Z）上对不齐，**增大**第三个值。
  - 如果旋转不稳定，**增大**第四个值。
  - 如果优化结果过于“刚性”，难以融合多个闭环，可以尝试将所有值**等比例减小**。

- 相对比重：决定单次匹配内部的“信任”分配
> 信息矩阵对角线元素 gicp_info_diag 的值是 [100.0, 100.0, 100.0, 10.0]。
> 
这四个值的相互比例告诉图优化器，在处理这一个回环约束时，应该如何权衡平移和旋转的误差。
前三个值（代表X, Y, Z平移）是最后一个值（代表旋转）的10倍。这意味着优化器会认为“平移”的匹配结果比“旋转”的结果可靠10倍。
因此，在优化时，如果平移和旋转的误差无法同时减小，优化器会优先保证平移的精度，宁可让旋转上产生更大的调整量。所以，您说的“相互比重”很重要是完全正确的，它决定了约束内部不同自由度的刚性。

- 绝对数值：决定本次匹配在整个地图中的“话语权”
> 信息矩阵的绝对数值大小，决定了这个回环约束相对于图中所有其他约束（比如连续帧之间的里程计约束）的权重。

  - 如果绝对值很大：意味着优化器认为这次回环检测非常准确，近乎“铁证”。当进行全局优化时，优化器会强制调整其他所有位姿来严格满足这个回环约束，哪怕这意味着整个轨迹会发生巨大的变形。
  - 如果绝对值很小：意味着优化器认为这次回环检测不太可信，只是一个“微弱的建议”。在全局优化时，如果满足这个回环会导致与其他约束产生巨大冲突，优化器可能会选择性地忽略它，只做微小的调整。

### 与 dr_noise_* 和 lc_edge_covs_type 的关系

调节 gicp_info_diag 绝对不能孤立进行，必须结合另外两个参数来理解：

1. dr_noise_* (里程计噪声)：这组参数定义了对**连续两个子地图之间（里程计）**的相对位姿的信任程度。dr_noise 值越大，代表里程计越不可信（信息值越小）。

平衡关系：图优化就是在“相信GICP约束”和“相信里程计约束”之间做权衡。
如果 gicp_info_diag 高，dr_noise 大 → 优化器：我主要听GICP的，里程计只是参考。
如果 gicp_info_diag 低，dr_noise 小 → 优化器：我主要沿着里程计走，GICP的修正只是微调。

2. lc_edge_covs_type (闭环协方差来源)：

当 lc_edge_covs_type 设置为 2 时，系统会尝试直接使用GICP算法自己估计的协方差来作为约束。这是一个更理想、自适应性更强的方式，因为它能反映每次配准的实际质量。在这种模式下，gicp_info_diag 可能会作为GICP协方差估计失败时的备用选项（Fallback），或者用来对GICP估计出的协方差进行缩放。
当 lc_edge_covs_type 设置为 0 时，系统会忽略GICP自己估计的协方差，并总是使用您在 gicp_info_diag 中提供的这个固定值。这对于调试和进行可重复的对照实验非常有用。

**里程计噪声 (Dead Reckoning Noise)**:

- `dr_noise_*`: `[x, y, z, roll, pitch, yaw]`
- **含义**: 定义了里程计（DR）推算位姿的不确定性。值越大，表示越不信任里程计，优化时会更倾向于采纳闭环边的修正。
- **调节逻辑**:
  - 如果轨迹在没有闭环的区域漂移严重，应**减小**相应的噪声值，以增强里程计的先验约束。
  - 如果存在有效的闭环，但轨迹未能被有效修正，说明里程计约束过强，此时应**增大**噪声值，以“放松”里程计的约束，让闭环修正发挥作用。

## 6. 闭环协方差来源（Loop Closure Covariance Type）

**相关参数**:
- `lc_edge_covs_type`

**目的**: 决定闭环边的协方差（不确定性）如何计算。

**选项**:

- `0`: 使用固定的协方差。适用于进行对照实验。
- `2`: **（推荐）** 使用 GICP 算法本身估计的协方差。这种方法是自适应的，能反映每次配准的实际质量，通常是最佳选择。
- `1`, `3`: 其他来源，当前配置下不常用。

---

## 快速决策口诀

- **“闭环太少”** → 降低 `overlap_coverage` 或减小 `submap_size`。
- **“闭环是错的”** → 减小 `gicp_max_correspondence_distance` 并提高 `overlap_coverage`。
- **“优化不听闭环的话”** → 增大 `dr_noise_*` 或减小 `gicp_info_diag`。
- **“局部地图对不齐”** → 增大 `gicp_info_diag` 中对应的分量。
- **“运行太慢”** → 增大下采样体素尺寸 (`downsampling_leaf_*`) 或放宽 GICP 收敛阈值。
- **“Z轴分层”** → 增大 `gicp_info_diag` 的 Z 分量，或减小 `downsampling_leaf_z`。
